# 新增设备

## 所需资料

至少需要一种机器控制依据：编程手册、官方 SDK/API、SCPI 命令表、Modbus 寄存器表或串口协议。用户手册用于补充安全限制和物理操作条件。

同时记录：

- 厂商、准确型号和固件；
- 通信方式和驱动依赖；
- 可用实机及安全测试条件；
- 已验证和未验证范围。

没有实机时可以提交接口、模拟器和测试，但必须标记为“文档支持”或“模拟验证”。

## 开发步骤

1. 复制 `rigol_agent/device_packs/template.py` 为 `<vendor>_<model>.py`。
2. 实现 Adapter 的 `invoke(tool, arguments)` 和 `close()`。
3. 连接后核验厂商与型号。
4. 先实现只读 `get_device_status`，并通过标准结果校验。
5. 从最小语义工具集开始，不开放原始协议命令。
6. 为每个工具定义严格 JSON Schema、风险等级、单位和范围。
7. 实现设备特有 `argument_validator` 和返回值校验。
8. 实现安全的本地规则规划器；无法识别的任务返回空计划。
9. 如需模拟器，模拟结果必须随设置变化，并明确区别于实机证据。
10. 在 `rigol_agent/device_packs/registry.py` 显式注册。
11. 添加契约、模拟和实机测试，更新能力与验证文档。

注册并重启服务后，设备会自动出现在 Web 设备列表中，不需要修改前端清单。

## 最低测试要求

- 重复 ID 和无效设备包拒绝；
- 错误型号拒绝；
- 缺失字段、额外字段、越界值、NaN 和 Infinity 拒绝；
- 未授权写入拒绝；
- 通信中断和重连；
- 写入成功但读回失败时的恢复；
- 恢复结果回读验证；
- 标准状态返回契约；
- 模型不可用时的本地回退；
- 序列号和密钥不进入日志与测试数据。

## Pull Request 内容

- 设备型号、固件和通信方式；
- 文档名称、版本和相关章节；
- 工具清单和风险等级；
- 实机测试条件和恢复结果；
- 未验证项目；
- 自动测试结果。
